## 2024-07-07 - Eliminate Redundant Database Queries and Waterfalls
**Learning:** In layout-heavy App Router architectures where layout data is fetched in `page.tsx` components rather than `layout.tsx`, it's easy to accidentally duplicate queries. For example, `profile/page.tsx` was manually running a `prisma.item.groupBy` to get item counts, and then immediately fetching `getItemTypesWithCounts` which runs the exact same query under the hood. It also executed queries sequentially rather than concurrently.
**Action:** Always check if required data is already being fetched by layout-level functions or shared components before executing redundant Prisma queries. Aggressively reuse fetched data arrays for multiple component props instead of running overlapping queries, and group all data fetching operations at the page level into a single `Promise.all` batch whenever possible to maximize concurrency and eliminate sequential waterfalls.
