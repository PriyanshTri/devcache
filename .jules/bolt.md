## 2024-06-25 - Group Page Data Fetching using Promise.all
**Learning:** Found sequential Prisma database queries (`prisma.item.count` and `prisma.collection.count`) in `src/app/profile/page.tsx` outside of the existing `Promise.all` batch. These sequential queries create waterfall bottlenecks, delaying subsequent queries and layout rendering unnecessarily. This codebase uses a layout architecture where individual pages (`page.tsx`) have to fetch common layout data instead of using `layout.tsx` effectively.
**Action:** When working on backend performance in App Router Server Components (`page.tsx`), identify all database calls within the component and group them together into a single `Promise.all` block. This maximizes query concurrency and drastically reduces total time to first byte, avoiding sequential waterfalls.
