## 2024-06-14 - Prevent Redundant Queries from Layout Data Needs
**Learning:** Because `DashboardLayout` doesn't use Next.js native layouts and requires shared layout data (like `itemTypes`, `sidebarCollections`) to be fetched in every individual `page.tsx`, it's easy to introduce redundant database queries. For example, `ProfilePage` queried `prisma.item.groupBy` to show stats, but `getItemTypesWithCounts` was already fetching the exact same data to pass down to the layout.
**Action:** Always inspect the data requirements of the shared layout components being fetched in a `page.tsx`. Often, the data needed for the page's body is a subset of, or identical to, the layout data. Reuse the results of layout data functions to eliminate redundant database queries and batch remaining queries using `Promise.all`.
