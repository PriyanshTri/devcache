## 2025-03-10 - Optimizing Next.js Page-Level Data Fetching
**Learning:** Shared layout data like sidebar collections or type counts often overlaps with page-specific data (e.g. usage breakdowns), leading to redundant duplicate queries (like calling `getItemTypesWithCounts` and `prisma.item.groupBy` separately for the same data). Also, running user verification `getUserWithSettings` sequentially blocks other non-dependent queries.
**Action:** Group all data-fetching operations at the page-level (including user fetch queries if the userId is already known from session auth) into a single `Promise.all` batch whenever possible to maximize concurrency and eliminate sequential waterfalls, and aggressively reuse the fetched data arrays for multiple component props instead of running overlapping queries.
