## 2024-05-25 - Icon-only buttons accessibility pattern
**Learning:** In top navigation bars, interactive elements using `<Button size="icon">` combined with Lucide icons (e.g. `<Menu>`, `<Search>`, `<Plus>`) consistently lack accessible names, making them invisible or confusing to screen reader users. The desktop search trigger acts as a simulated button (`<button>`) but safely relies on its visible inner text `<span>` rather than an aria-label.
**Action:** When working on navigation or header components, immediately verify that any icon-only `<Button>` or `<button>` element includes an explicit `aria-label` that describes its function. Ensure simulated buttons (e.g. `<Link>` acting as an icon button) also receive an `aria-label`. If a button contains visible descriptive text within its bounds, an `aria-label` is not strictly necessary.
