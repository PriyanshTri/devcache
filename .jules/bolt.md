## 2026-05-27 - Batching Queries & Reusing Layout Data in Server Components
**Learning:** In Next.js App Router, layout-level functions (like `getItemTypesWithCounts` for `DashboardLayout`) and page-level data requirements often overlap. In `src/app/profile/page.tsx`, the same data was being fetched twice (once via `groupBy` in the page, and once inside `getItemTypesWithCounts` for the layout). Also, independent queries were scattered across multiple `await` statements, causing sequential waterfalls.
**Action:** Always check if required data is already being fetched by layout-level functions before executing redundant Prisma queries. Group all independent queries (e.g., counts, layouts) into a single `Promise.all` at the top of the server component to minimize overall database latency.
